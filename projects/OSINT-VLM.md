# OSINT-VLM · 多模态目标识别与场景描述微调实验

---

## 项目概述

本项目基于开源多模态大模型 **InternVL2-8B**，通过 LoRA 微调，提升模型在无人机视角下地面军事目标的**识别与场景描述**能力。

不同于传统目标检测仅输出"类别 + 位置"，本项目利用多模态大模型的视觉 + 语言能力，设计了三层结构化输出：

1. **目标识别**：类别 + 位置
2. **场景关系描述**：队形、间距、运动状态
3. **基础态势推断**：保守的自然语言推断

所有数据均来自公开学术数据集（VisDrone2019、Roboflow Military Vehicle Recognition、ADOMVI、VSAI、Mendeley）及官方媒体公开图像，不涉及任何保密或敏感渠道。

### 项目角色

**AI 训练师**：负责标注规范制定、AI 辅助标注执行、数据质量管控及效果验证。

### 技术路线

| 维度 | 配置 |
|------|------|
| 基础模型 | InternVL2-8B（上海 AI Lab 开源） |
| 微调方式 | LoRA（lora_r=64, lora_alpha=128, lr=2e-4, epoch=3） |
| 训练环境 | AutoDL 云平台 A100 40G |
| 标注工具 | Label Studio（本地部署版） |
| 类目体系 | 5 类（战斗车辆 / 运输车辆 / 后勤车辆 / 人员 / 班组） |
| 数据规模 | 约 1700 张，按 7:1.5:1.5 划分 |

## 数据方案

### 核心定位

本项目面向无人机光学视角下的地面军事目标识别**与场景描述**任务，数据策略采用"目标特征 + 视角特征"分层组合：

- **军事目标特征**：通过专门的军事目标识别开源数据集学习
- **无人机视角特征**：通过消费级无人机航拍数据集学习
- **国内装备样本**：通过官方媒体公开内容补充
- **场景描述**：在目标标注基础上，由 AI 训练师人工撰写场景描述文本

### 数据来源

| 数据集 | 预计图像数 | 主要贡献类别 |
|--------|-----------|------------|
| Roboflow Military Vehicle Recognition | ~500 张 | 战斗车辆 / 运输车辆 / 人员 / 班组 |
| ADOMVI | ~300 张 | 战斗车辆 / 运输车辆 / 后勤车辆 |
| VSAI | ~300 张 | 视角特征学习（多类别参考样本） |
| VisDrone2019-DET | ~200 张 | 班组 / 人员（人员场景） |
| 央媒官方图像截帧 | ~150 张 | 后勤车辆 / 战斗车辆（国内装备） |
| 网络公开军事科普 | ~100 张 | 多类别多样性补充 |
| Mendeley 军民车辆 | ~150 张 | 后勤车辆（军民判别辅助） |
| **合计** | **~1,700 张** | — |

> **注**：原 UAV-tracking-tank 数据集因包含游戏画面等非真实场景素材，已从方案中移除。

### 类目体系（5 类最终版）

经过迭代优化，将原 8 类合并为 5 类，每类样本量更充足，更适合 LoRA 微调数据量级：

| 类别名 | 包含范围 | 数据规模 |
|--------|---------|---------|
| 战斗车辆 | 坦克、AFV、突击车、自行火炮等以战斗为主功能的车辆 | ~550 张 |
| 运输车辆 | 装甲运兵车、军用卡车、越野运输车等 | ~350 张 |
| 后勤车辆 | 指挥车、通信车、工程车、油罐车等保障类车辆 | ~380 张 |
| 人员 | 单兵或 2 人以下，无明显队形特征 | ~400 张 |
| 班组 | 3 人及以上，具有可识别队形特征 | ~220 张 |

**合并逻辑**：AFV 与坦克均为"装甲战斗"角色，外观特征接近；APC 与 LAV 均为"装甲运输/轻型机动"角色；军用卡车与 MEV 均为"非战斗保障"角色。合并后每类样本量均达到 LoRA 微调可学的最低标准。

### 数据集划分

| 子集 | 比例 | 用途 |
|------|------|------|
| 训练集 train | 70%（~770 张） | 模型微调训练 |
| 验证集 val | 15%（~165 张） | 训练过程监控 |
| 测试集 test | 15%（~165 张） | 最终效果对比评估 |

### 场景描述文本计划

每张图像配套一段 50–150 字的中文场景描述，包含三个层次：

| 层次 | 内容 | 示例 |
|------|------|------|
| 客观识别 | 列出图中可见目标的类型与数量 | "图中可见 2 辆运输车辆与约 6 名单兵" |
| 关系描述 | 描述目标的空间关系、队形、运动状态 | "2 辆装甲车呈纵队行进，间隔约 15 米，单兵分散在两侧" |
| 基础推断 | 给出保守的态势推断 | "队形紧密，推测为非战斗状态下的常规机动" |

约 1,700 张图全部配套场景描述，由 AI 训练师人工撰写，参考 Qwen-VL / DeepSeek 预生成草稿后逐张审核修正。

## 标注体系

标注采用"目标框标注 + 场景描述文本"双轨方式，工具为 Label Studio（本地部署），输出 COCO JSON 格式。

### 标注框规则

**基本原则**：标注框应紧贴目标外轮廓，四边与目标边缘保留 2–3 像素余量；旋转目标使用水平外接矩形框（HBB）。

**各类别画框要点**：
- **战斗车辆 / 运输车辆**：框住车体 + 炮塔 + 炮管（炮管朝向不改变框形状，但伸出车体的部分必须包含在内）
- **后勤车辆**：必须包含驾驶室、货厢/装载区；起重臂、推土铲、雷达天线须包含在框内
- **人员**：从头顶（含头盔）到脚底，包含背包、枪械
- **班组**：最外侧人员形成的最小外接矩形；触发条件为 3 人及以上 + 可识别队形特征

### 关键判别规则

**战斗 vs 运输**：看主武器。大口径主炮（>40mm）或中口径机炮 → 战斗车辆；方正大箱体、武器较小或无主炮 → 运输车辆。

**后勤车辆**：有大型货厢、罐体结构、工程臂、通信天线、起重机构之一 → 后勤车辆；普通军用越野车无法确定用途时默认归入此类。

**军民判别**优先级：迷彩涂装/军种标志 → 武器/装甲改装 → 场景上下文 → 典型军用型号 → 以上都无法确定则跳过不标。

**班组判定**以队形为核心，非单纯人数：3 人及以上 + 有队形（纵队行进、横队展开、散兵线、车辆伴随警戒等）→ 班组；3 人及以上但无队形 → 分别标注为多个"人员"。

### 边界情况处理

| 类型 | 标准 | 处理方式 |
|------|------|---------|
| 遮挡 25%–74% | 可见 26%–75% | 标注可见部分，标记遮挡级别 |
| 遮挡 < 25% | 可见 < 25% | 跳过不标 |
| 图像边缘截断 ≤75% | — | 框延伸至图像边缘，标记截断属性 |
| 模糊目标（像素 < 20×20） | — | 跳过 |
| 烟雾遮挡 > 50% | — | 直接跳过 |
| 屏幕/海报/CG 中的目标 | — | 跳过不标 |

### 场景描述标注规范

**必须遵守**：使用中文陈述句；推断必须用"推测""可能""疑似"等弱表述；数量描述用"约"或"近"，避免精确数字；每段控制在 50–150 字。

**严格禁止**：涉及具体战术建议或火力推演；提及具体地理位置或部队番号；对识别对象的政治立场评价；超出图像可见信息的主观臆测。

**撰写流程**：
1. 使用 Qwen-VL 对图像批量生成场景描述初稿
2. 使用 DeepSeek 对初稿进行文本规范化润色
3. AI 训练师逐张审核修正（目标类型/数量、关系描述、推断合理性）
4. 每批次随机抽取 10% 二次复查

## 质检流程

标注质检采用"AI 预标注 + 人工全量审核 + 批次抽检"三阶段模式。

### 质检阶段

**阶段一 · AI 预标注**：使用 InternVL 原始模型批量预标注（置信度阈值 0.5），导入 Label Studio 后由人工逐张审核、修正错误框、补充漏标。

**阶段二 · 人工全量质检**：所有图像标注完成后逐张复查；每批次完成后随机抽取 10% 进行二次复查；单张图像存在 2 个及以上明显错误则打回重标。

### 单框质量评分（四级制）

| 等级 | 标准 | 处理 |
|------|------|------|
| A · 优秀 | 框边误差 ≤3px，类别准确，属性完整 | 入库 |
| B · 合格 | 框边误差 ≤5px，类别准确，属性基本完整 | 入库 |
| C · 待修正 | 框边误差 6–10px 或属性缺失 | 修正后入库 |
| D · 不合格 | 框边误差 >10px 或类别错误或漏标 | 重标 |

### 批次质量指标

| 指标 | 目标值 | 警戒值 |
|------|-------|-------|
| 整体 A 级框比例 | ≥70% | <50% 触发批次重审 |
| B 级及以上框比例 | ≥95% | <90% 触发批次重审 |
| 类别准确率 | ≥95% | <93% 触发规范复训 |
| 漏标率 | ≤3% | >5% 触发流程优化 |

### 团队分工与排期

**团队构成（共 10 人）**：项目负责人 1 人（规划/规范/进度）、标注组 6 人、质检组 2 人、规范组 1 人。

**标注排期（3 周）**：

| 周次 | 主要工作 |
|------|---------|
| 第 1 周 | 规范培训（1 天）+ 第一批标注 600 张 + 第一轮质检 |
| 第 2 周 | 第二批标注 700 张 + 第二轮质检 + 问题返修 |
| 第 3 周 | 第三批标注 400 张 + 全量终审 + 10% 抽检 + 数据交付 |

效率基准：单张图像人工处理约 5–8 分钟（含框审核 + 描述润色），6 人标注组每日合计处理约 220 张，1700 张预计 8 个有效工作日完成标注。

## LoRA 配置说明

### 模型选型：为什么选 InternVL2-8B

| 考量维度 | 说明 |
|---------|------|
| 识别性能 | 在细粒度、小目标识别 benchmark 上表现优秀 |
| 中文适配 | 原生支持中文，适合中文标签体系 |
| 微调文档 | 官方提供完整 LoRA 微调脚本和文档 |
| 显存需求 | 8B 参数量在 A100 40G 上可稳定运行 |

### 为什么用 LoRA 而不是全量微调

全量微调需要约 80G+ 显存，成本过高。LoRA 只训练低秩适配矩阵，显存需求降低约 70%，在垂直领域小数据集上效果与全量微调差距可接受，且训练速度更快，适合快速迭代验证。

### 关键参数配置

**LoRA 参数**：

| 参数 | 配置值 | 选择理由 |
|------|-------|---------|
| `lora_r` | 64 | 秩越高表达能力越强，64 在效果和显存间取得平衡 |
| `lora_alpha` | 128 | 通常设为 r 的 2 倍，控制 LoRA 缩放比例 |
| `lora_dropout` | 0.05 | 轻度 dropout 防止过拟合，数据量小时适当保留 |
| `target_modules` | q_proj, v_proj | 对注意力层的查询和值矩阵做适配，效果稳定 |

**训练参数**：

| 参数 | 配置值 | 选择理由 |
|------|-------|---------|
| `learning_rate` | 2e-4 | LoRA 微调常用范围，过高易震荡，过低收敛慢 |
| `batch_size` | 8 | A100 40G 显存下稳定运行的最大批次 |
| `gradient_accumulation_steps` | 4 | 等效 batch_size=32，提升训练稳定性 |
| `num_epochs` | 3 | 数据量约 1100 张，3 轮足够收敛，避免过拟合 |
| `warmup_ratio` | 0.03 | 前 3% 步骤线性预热，防止初期学习率过大 |
| `lr_scheduler` | cosine | 余弦衰减，训练后期平滑降低学习率 |
| `max_seq_length` | 2048 | 覆盖图像 token + 文本标签的上下文长度 |

### 训练环境

| 项目 | 配置 |
|------|------|
| 云平台 | AutoDL |
| GPU | A100 40G × 1 |
| CUDA | 11.8 |
| Python | 3.10 |
| PyTorch | 2.1.0 |
| 依赖框架 | transformers 4.37+, peft 0.8+, deepspeed 0.13+ |

### 任务设计

**输入格式**：图像 + 提示词（如"请识别图像中的地面目标，输出目标类别和位置描述"）

**输出格式**：结构化识别结果，包含目标类别、位置区域描述，以及图像级场景描述文本。

**主任务**：目标类别识别（分类）；**辅助任务**：目标位置描述（区域级，非像素级检测）。

### 过拟合风险控制

| 措施 | 说明 |
|------|------|
| 数据增强 | 随机水平翻转、随机亮度对比度调整、随机裁剪 |
| lora_dropout | 轻度正则化 |
| 验证集监控 | 每个 epoch 后评估验证集，loss 上升则早停 |
| 训练轮次控制 | 不超过 5 轮，观察验证集曲线决定最终轮次 |
