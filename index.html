C
Annotation Design · Multi-Scene

跨场景标注规则文档编撰实践

从真实数据出发，独立完成 7 类训练场景的标注规则设计：需求理解 → 维度拆解 → 优先级定义 → 速查卡提炼。 覆盖 SFT 与 RLHF 完整训练链路，每个场景均有专项规则与边界 case 处理。

单轮问答
P0 内容准确 · 指令遵从
P1 内容完整
P2 表达质量

单轮场景核心是「听懂 query」，指令遵从优先级与内容准确并列 P0。

多轮对话
P0 上下文一致 · 指代理解
P1 回答质量

指代不明是多轮场景最高频失守点，须在全局视角和单条 response 两个层次同时核查。

Reward Model
P0 内容准确 · 内容完整
P1 指令遵从 · 表达质量

无效回答不能排末位——它会作为负样本污染偏好信号，须直接剔除不参与排序。

CoT 思维链
think P0 推理有效 · 推理覆盖
response P0 内容完整 · 指令

think 与 response 捆绑进入 SFT，response 不达标则整条数据无效，两者须同等把关。

RAG
有效性 材料可用 · prompt 可用
P0 忠实材料 · 内容完整

材料可用性前置于内容质量，材料不可用则后续标注全部失效。

Agent
P0 工具调用准确 · 任务完成
P1 内容准确 · 上下文一致

核心反模式：以对话拖延代替工具调用。融合 CoT、多轮、单轮三类场景规则。

专项 · 语音助手
P0 人设一致 · 信息准确
P1 语言自然度 · 任务完成

语音场景下模板语危害高于通用场景——「一直都在哦」比事实错误更影响训练质量。

05 Manifesto

What I believe about training AI.

这不是宣言,是我目前的认知。一定会变,但写下来就是承诺。

01

训练 AI 的本质,是把人类判断显式化。

一个标注员说"这个回答不好",这不是评分,是直觉。把直觉拆成 5 个可勾选维度——这才是工程。

02

Bad Case 比 Good Case 信息量大 100 倍。

一千个正确告诉你"模型能做这个任务",一个错误告诉你"模型在这一步崩了"——后者才是改进的入口。

03

评估比 Prompt 更难,也更重要。

行业里大多数人在比谁的 Prompt 巧,但真正稳住产品质量的,是评估集的覆盖度与一致性。

04

标注员不是廉价劳动力,是产品质量的最后一道闸。

一份好的标注规范,能让 100 个标注员产出和 5 个专家一致的结果——这是流程工程,不是体力活。

05

AI 训练师 ≠ Prompt 工程师。

Prompt 工程师在用模型,AI 训练师在改造模型。前者优化输入,后者重塑分布。
